# ADR-0015 口座の「現在の残高」設定（残高調整）を追加する

- 状態: Accepted (2026-11-09, 本人の決定による)

## 決定

口座の作成・編集時に **「現在の残高」を設定できる** ようにする（決定 P）。
口座残高の算出方法（取引の合計）は維持したまま、設定値と算出値の差額の扱いを
保存時に選べるようにする。マネーフォワードの残高調整に倣った形式。

1. **差額を「残高調整」の取引として記録する（既定）**
   - 取引種別に `adjustment`（残高調整）を追加し、差額（符号付き）を
     保存日（Asia/Tokyo の当日）の取引として1件登録する。メモは「残高調整」、カテゴリなし。
   - 残高の算出では残高調整を符号付きで加算する。
   - 月次収支・カテゴリ別集計には含めない（集計は income / expense のみが対象のため自動的に除外される）。
   - 残高調整の取引は取引一覧に「残高調整」と表示し、編集は不可（API でも 400）とする。
     削除（論理削除）は可能で、削除すると残高は調整前に戻る。
   - CSV では収支種別ラベル「残高調整」で入出力し、符号付き金額のまま往復できるようにする。
2. **取引に記録しない**
   - 差額は取引として残さず、口座の `balance_offset`（未記録の調整累積）に加算して保持する。
   - 残高 = 取引の合計 + balance_offset。履歴には残らない代わりに、残高だけを実態に合わせられる。
3. **新規作成時も設定できる**。作成直後の算出残高は 0 のため、設定値そのものが差額になる。
4. **マイナス残高も許可する**（クレジットカード口座等）。残高・差額に下限は設けない。

## 理由

- 既存の銀行口座などを実残高で登録し始めたい、計算が合わなくなったときに
  実残高へ寄せたい、という本人の要望（2026-11-09）。
- 記録するかどうかで「履歴として残したい／残したくない」が分かれるため、
  本人の指示で保存時に選べる形式にした。

## 影響

- DB: Flyway V5 で transactions.type に 'adjustment' を追加し、accounts に balance_offset 列を追加する。
- API: 口座の作成・更新リクエストに currentBalance（任意）と recordAdjustment（既定 true）を追加する。
- Web: 口座フォームに「現在の残高」入力と「差額を『残高調整』として取引に記録する」チェックを追加する。
  取引一覧では残高調整を専用表示にし、編集ボタンを出さない。
- 要件定義（requirements.md）の §3.2「残高の直接編集はしない」は本 ADR で置き換える。
