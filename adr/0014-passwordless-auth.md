# ADR-0014 認証をパスワードレス（メール OTP ＋ パスキー）に移行する

- 状態: Accepted (2026-11-09, 本人の指示による)

## 決定

認証方式を **メール + パスワード（決定 B2）からパスワードレスへ全面的に置き換える**（決定 O）。

1. **登録・ログインはメール OTP（ワンタイムコード）に統一する**
   - メールアドレス宛に 6 桁コードを送り、入力が一致したら認証成立とする。
     新規・既存を区別しない単一フローとし、新規の場合はコード発行時に任意で表示名を受け取り、
     検証成功時にアカウント＋テナント＋初期カテゴリを作成する。
   - コードを受け取れること自体がメールアドレスの本人確認になるため、従来なかった
     「登録時のメールアドレス本人認証」も同時に満たす。
   - コードの仕様: 有効期限 10 分、検証試行は 5 回まで、再送は 60 秒間隔から、
     DB には SHA-256 ハッシュのみ保存し、発行のたびに旧コードを無効化する。
     応答は登録済みかどうかを漏らさない形（常に同一）にする。
   - 認証後のセッションは従来どおり JWT（変更なし）。
2. **パスワード認証は撤去する**
   - `/api/auth/register`・`/api/auth/login` は廃止し、users.password_hash 列も
     Flyway マイグレーションで削除する。既存アカウントは同じメールアドレスで
     OTP ログインできるため、移行による締め出しは発生しない。
3. **メール送信は SMTP の共通インターフェースで抽象化する**
   - 送信先・認証情報は環境変数（MAIL_MODE / MAIL_HOST / MAIL_PORT / MAIL_USERNAME /
     MAIL_PASSWORD / MAIL_FROM）で設定し、コード側は特定の送信サービスに依存しない。
   - 開発時は MAIL_MODE=log でコードをサーバーログに出力し、送信基盤なしで動作確認と
     E2E（API ログからコードを拾う）を可能にする。
   - 本番の送信サービス選定はデプロイ時に行う（第一候補: Oracle Cloud Email Delivery。
     SMTP のため設定変更のみで差し替え可能）。
4. **パスキー（WebAuthn）を追加する**（後続 PR で実装）
   - ログイン後に設定画面からパスキーを登録できるようにし（任意・複数可）、
     ログイン画面からはユーザー名なし（discoverable credential）でログインできるようにする。
   - 本番では HTTPS が前提（ドメイン取得・証明書はデプロイ時の作業とする）。

## 理由

- 現状のメール + パスワード登録は、メールアドレスが本人のものか確認しておらず、
  他人のアドレスで登録できてしまう（本人の指摘、2026-11-09）。
- パスワードレス化で、パスワードの管理負担と漏洩・使い回しリスクをなくし、
  パスキーで日常のログインも簡単にしたいという本人の要望による。

## 影響

- API: AuthController の再構成、login_codes テーブルの追加（V2）、password_hash の削除（V3）、
  spring-boot-starter-mail の追加、PasswordEncoder の撤去。
- Web: ログイン画面を「メール入力 → コード入力」の 2 ステップに作り替える。
- テスト: API 単体テストと E2E の認証フロー（登録・ログイン手順）を OTP 方式へ追随させる。
- 要件定義（requirements.md）の認証記述と決定 B2 は本 ADR / 決定 O で置き換える。
